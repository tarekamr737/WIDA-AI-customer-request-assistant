# AGENTS.md — WIDA AI Customer Request Assistant

## Mission
Build the WIDA practical-task solution end to end: a runnable AI assistant that processes B2B customer requests using the supplied Horizon reference files.

## Source of truth
1. `references/02_Service_Catalog.txt`
2. `references/03_Operating_Policies.txt`
3. `references/04_Output_Template.txt`
4. Remaining supplied Horizon files for context/tests.
Never invent services, policies, prices, deadlines, customer data, or missing facts.

## Optimize for
- Working demo first.
- Correctness and explainability.
- Small, readable code.
- Fast live modification.
- Low LLM/token usage.
- Easy technical-review defense.

## Required approach
- Python 3.11+.
- Streamlit for the runnable UI.
- Pydantic for structured schemas.
- OpenAI-compatible client behind one small adapter.
- CSV for local persistence.
- Pytest for deterministic tests.
- No LangChain, CrewAI, vector DB, agent framework, database server, or unnecessary infrastructure.
- One LLM call per request; allow at most one repair retry if structured output is invalid.
- LLM does extraction + service classification only.
- Python does policy enforcement, missing-field checks, template rendering, storage, and review state.
- Read references and prompt files at request time; do not bake their content into code.
- Never hardcode answers for Requests A–E.

## Product behavior
- Accept pasted request text or uploaded `.txt`, `.pdf`, or `.docx`.
- Extract organization, contact name/role, contact method, need, requested deadline, commercial-register status, and missing fields.
- Classify only against service IDs 1–8 from the catalog.
- Allow primary + secondary service only when evidence is clear.
- Return `null`/unknown when information is absent.
- Never force an unclear/out-of-scope request into a service.
- Apply operating policies deterministically.
- Render the internal summary in the supplied template order.
- Auto-save every processed result with review status `بانتظار المراجعة`.
- Allow a human to edit the structured fields, then approve.
- Approval updates the stored row to `تمت المراجعة`.
- Do not implement outbound customer messaging.

## Maintainability
- Keep prompt in `prompts/analyze_request.md`.
- Keep reference files in `references/`.
- Parse service durations and the minimum-execution-days policy from the current files.
- A simple edit to catalog/policy/prompt files must take effect after rerun without rebuilding.
- Separate UI, orchestration, LLM, policy, rendering, parsing, and storage.

## Reliability
- Validate all LLM JSON with Pydantic.
- Reject service IDs outside the loaded catalog.
- Treat unreadable/empty files as user errors, not AI guesses.
- If the LLM fails, show a recoverable error and do not fabricate output.
- Never let policy logic depend on prose generated by the LLM.
- Preserve the original request text for audit/debugging.
- Do not log API keys.

## Security
- Secrets only in `.env`; commit `.env.example`, never `.env`.
- Add `.env`, caches, generated CSV data, and local artifacts to `.gitignore`.
- Do not print environment values or secret-bearing exceptions.

## Implementation discipline
- Read `PRODUCT.md`, then `ARCHITECTURE.md`, then execute `TASKS.md`.
- Build the vertical slice before polish.
- Keep functions small and typed.
- Prefer standard library where practical.
- Do not add features not required by acceptance criteria.
- Do not redesign supplied business rules.
- Update `TASKS.md` checkboxes as work completes.
- Create a concise one-page `README.md` only after the app works.

## Quality gates
Before stopping:
- `streamlit run app.py` starts cleanly.
- Pasted text works.
- At least one uploaded file works.
- Requests A–E can be processed without hardcoded branching.
- Policy tests pass.
- Human approval changes review state.
- CSV persistence works.
- Missing API key produces a clear setup message.
- No secrets are committed.
- README contains setup, run, tools, env, reference updates, prompt location, and limitations.

## Stop condition
Stop when all Must acceptance criteria in `PRODUCT.md` pass. Leave optional improvements unimplemented unless all required work is complete.
